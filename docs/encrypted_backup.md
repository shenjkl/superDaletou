# 口令加密的数据库快照

本机命令可为当前研究数据库创建加密快照、在内存中检查加密快照，或从快照准备隔离候选。快照包含数据库中的研究记录、模型、开奖观察和保存的来源原文；这些原文可能含个人信息、凭据或本机路径。快照不是经过脱敏的研究导出，也不能据此认定完整备份和正式恢复已验收。当前仅支持数据库大小不超过 64 MiB，需要项目要求的 Python 3.12 与 `requirements.txt` 中的 `cryptography`。

也可在本机服务运行时，进入“数据与规则 → 加密数据库快照 → 创建加密快照”，输入并确认口令、勾选资料范围后生成下载。页面通过本机同源会话及写入令牌提交口令，提交后清空表单；服务不将口令写入应用数据库或应用请求日志。浏览器实际保存位置取决于其下载设置，应确认文件已保存。页面也支持口令认证与内存检查、准备隔离候选、复核候选及激活到新的数据库路径。恢复准备请求在 IndexedDB 中只保存源/目标路径、确认项和请求标识，不保存口令；结果不确定时可查询、继续原请求、封止或关联到新目标重试。浏览器、操作系统、进程内存或其他软件可能自行保存数据，不能据此保证口令从未被留存。

创建新的加密文件（目标所在目录须已存在，文件不能已存在）：

```powershell
python -m dlt.encrypted_backup create "runtime/research.sqlite3" "D:/受保护目录/research.dltbak"
```

可先在内存中认证并检查加密快照，不创建明文候选文件：

```powershell
python -m dlt.encrypted_backup inspect "D:/受保护目录/research.dltbak"
```

该命令解密到 SQLite 内存连接后运行现有已选完整性检查，并输出不含数据库路径及记录正文的 JSON 报告。退出码 0 表示这些已实现检查通过；2 表示检查失败、不完整或命令失败。此检查不验证来源真实性、完整恢复合同或业务运行可用性，也不会移除候选隔离标记或切换运行数据库。

程序在终端交互要求输入并再次确认至少 12 个字符的口令；口令不会作为命令行参数。请单独保管口令：遗失后系统无法解密。加密使用随机盐、随机 nonce、scrypt（N=32768、r=8、p=1）及 AES-256-GCM，文件头作为认证数据。加密保护不等于消除敏感内容；有口令的人可读取快照，弱口令也可能被离线猜测。源数据库及其现存 SQLite 侧车必须位于受保护目录且通过 ACL/mode 检查，否则备份和原始隔离副本操作拒绝读取，不自动改写既有权限。源数据库可能继续包含明文资料。程序不保证清除进程内存、交换文件或系统崩溃转储。

从快照准备候选文件：

```powershell
python -m dlt.encrypted_backup prepare "D:/受保护目录/research.dltbak" "D:/受保护目录/isolated.sqlite3" --acknowledge-plaintext
```

**候选文件和准备期间的临时文件是明文，包含原始资料及可能的敏感信息。** 程序在创建临时明文文件前、发布前后检查目标目录和候选文件权限；检查失败时不会继续正常发布流程。Windows 检查允许当前用户、SYSTEM 和本机 Administrators 的相关访问 ACE；POSIX 要求目录 mode 为 `0700`、文件为 `0600`。SQLite 写入完成并关闭连接后，程序会在原子发布候选前对临时数据库文件调用 `fsync`；该文件同步不保证突然断电时父目录中的发布名称一定持久，也不替代真实文件系统和恢复验收。无法核验权限时按失败处理。该检查不验证账户管理、静态加密或并发 ACL 修改，也不消除目录和文件系统语义差异。`--acknowledge-plaintext` 表示理解候选包含明文资料。口令错误、文件认证失败、检查不通过、目标或其 SQLite 日志已存在时不会覆盖原文件；权限检查在发布后失败时会明确报告候选已发布且仍隔离，禁止启动。进程意外终止或清理失败可能留下 `.dlt-recovery-*.tmp` 明文文件；结果中的 `staging_cleanup: failed` 和退出码 3 表示需要检查目标目录。正常成功为退出码 0，检查/发布失败为退出码 2。创建阶段的 `.dlt-encrypted-*.tmp` 为加密内容，异常退出也可能残留。

SQLite 一致备份先在内存中读取，包括备份时已提交但尚未检查点的 WAL 数据；创建加密快照时不写入明文数据库副本。依据 [SQLite 反序列化接口说明](https://www.sqlite.org/c3ref/deserialize.html)，内存快照的 WAL 文件头在反序列化前调整为回滚模式，源数据库不受修改。认证成功后才在内存解密，随后在目标目录建立候选、执行现有部分完整性检查并添加隔离标记。本版服务与后台执行器拒绝运行隔离候选，恢复前不会自动运行旧计划；旧版程序和直接 SQLite 操作不受该标记约束。

候选文件发布后，可在后续使用前重新检查磁盘上的隔离副本：

```powershell
python -m dlt.encrypted_backup verify-candidate "D:/受保护目录/isolated.sqlite3"
```

该命令只读检查已实现的数据库结构、引用及业务摘要，并要求隔离标记仍有效、候选没有 WAL/SHM/journal 旁路文件；不需要备份口令，不会移除隔离或启动计划。退出码 0 只表示当前已实现检查通过，不能作为完整恢复认证或启用许可。检查期间不要让其他进程打开或修改候选。

数据与规则页也提供快照口令认证及内存检查（不写明文文件）、候选准备、隔离候选复核和激活操作。页面要求填写本机服务可访问的绝对文件路径，路径及口令只提交到受本机同源会话和 CSRF 校验保护的本地服务；口令在提交后从表单清除。候选及恢复副本仍写入用户指定路径，服务在创建前检查目标目录权限，检查未通过则阻断。页面还可只读复核已激活恢复副本是否通过当前完整性检查且没有隔离标记；该结果不证明完整业务或运行时验收。若操作期间连接中断，先使用候选/恢复副本复核入口确认磁盘状态，再决定后续操作，不要盲目重试。页面复核与命令行复核执行相同的当前检查。

加密快照下载使用二进制 HTTP 响应，不写业务台账。传输中断、会话失效、服务端错误或成功响应体无法完整读取时，页面会标记连接状态待重新核验并停止下载；输入口令已在发送前从表单清除。只有完整收到当前连接世代的二进制内容才触发浏览器下载。

将复核通过的隔离候选恢复为**新的可运行数据库副本**（不会覆盖当前运行库，也不会改动隔离候选）：

```powershell
python -m dlt.encrypted_backup activate-candidate "D:/受保护目录/isolated.sqlite3" "D:/受保护目录/restored.sqlite3" --acknowledge-plaintext --enable-restored-plans
```

两个确认参数都必须提供：输出副本为明文；启动该副本时其中原有的已启用计划可能开始执行。程序要求目标数据库及其 SQLite 日志不存在；将复制和回执写入的新副本关闭后先调用 `fsync`，再以隔离状态原子发布，然后移除新副本的隔离标记并执行已实现的完整性检查。检查失败时会尝试重新隔离目标；失败流程不修改原库或隔离候选，也不会留下可运行目标。该命令不会改动服务配置；明确选择新数据库运行时才启动服务：

```powershell
python -m dlt.app --db "D:/受保护目录/restored.sqlite3"
```

Windows ACL 检查、POSIX mode 检查及候选文件检查已经接入候选准备、复核与激活路径；候选和恢复副本相关 SQLite 路径的现存组成部分也拒绝符号链接及 Windows reparse point。它们不防止检查后并发修改 ACL，也不验证主机账户和管理员策略是否可信。目标机器的依赖兼容及启动后全业务验收仍需单独处理。这里的“通过”限于当前 `dlt.integrity.check_database` 已实现的检查，不等同于独立来源认证、每项业务能力运行验证或完整恢复认证。

创建快照只检查 SQLite 基本完整性与外键；准备候选时先在内存执行[已实现的部分业务检查](data_integrity.md)，通过后才写入明文临时文件，发布后再检查一次磁盘候选。任一检查失败或不完整时都不发布候选。以上检查不证明来源、前瞻时点或完整恢复合同。页面现提供隔离候选准备、复核及新路径激活，但不能替代完整业务验证、运行时兼容、完整恢复认证或服务配置切换；不能将当前检查通过直接当成正式恢复验收。目标目录应避免其他进程同时操作同名文件；不同文件系统及非 Windows 环境尚需验收。

## 浏览器恢复写入待确认记录

网页恢复候选准备与恢复副本激活使用持久请求键和状态记录。发送前浏览器将请求写入 IndexedDB；准备候选所需的快照口令只在当前表单提交时传输，不保存于待确认项。页面提供查询、未知时继续原请求、封止和已封止后的换新目标关联重试。目标数据库内的不可变恢复回执用于在服务进程中断后识别目标文件并补记服务端接受结果。封止会等待当前恢复文件操作结束。

只有在真实浏览器中验证 IndexedDB/Web Locks、HTTP 响应丢失、并发封止、浏览器刷新和服务重启后，才能确认完整恢复写入闭环；静态语法检查不能替代这些验收。

服务端在恢复文件操作前先核对关联重试链和同目标待确认封止；无效、内容不一致或重复重试会在创建目标文件前拒绝。恢复写入的封止必须通过与文件操作共用锁的专用路由。
