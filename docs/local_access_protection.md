# 本机服务数据访问保护

Web 服务仅绑定 `127.0.0.1`，并使用短期会话、同源与 CSRF 校验保护浏览器请求。Web 服务和独立的 `dlt.worker` 计划管理/执行命令共用数据库文件系统访问权限检查，避免把网络只监听本机误当成对其他本机账户的数据隔离。

## 启动检查

- 数据库路径的现存组成部分不能是符号链接；Windows 上也拒绝 reparse point（包括 junction）。检查发生在路径解析和 SQLite 只读隔离探测前。服务检查实际父目录权限。
- 父目录不存在时，服务创建该目录并将权限限定为当前账户、SYSTEM 和本机 Administrators；POSIX 系统使用目录 mode `0700`。
- 已存在的数据库目录、主数据库文件及 `-wal`、`-shm`、`-journal` 侧车文件会在数据库初始化前检查；所有表初始化后、服务开始监听前会再次检查目录、数据库及侧车文件。目录、数据库或侧车是 Windows reparse point 时也会拒绝启动。任一检查失败时拒绝启动，不会自动修改既有目录或文件 ACL。
- 新建 SQLite 主数据库完成初始化后，POSIX 系统将文件权限设为 `0600`；Windows 新数据库和 SQLite 侧车文件继承受保护目录 ACL。启动后出现的 ACL 改动不由本机服务持续监视。

Windows 检查允许当前账户、SYSTEM 和 Administrators 的文件访问 ACE；其他 SID 只要获准 `FullControl` 中除同步标志外的任一权限，服务就拒绝启动。POSIX 检查目录不得向 group/other 开放访问，既有文件不得向 group/other 开放读写或执行权限。

## 既有数据库

如果现有目录或数据库不符合权限要求，服务会停止，不会替用户递归重写包含其他文件的目录 ACL。用户应将数据库迁移到仅本人可访问的目录，或由本人审核后单独调整目标目录与数据库文件权限，再重新启动。加密快照和恢复候选另按[加密备份说明](encrypted_backup.md)执行保护检查。

该启动合同不验证本机账户是否可信、管理员策略、磁盘静态加密、恶意进程、文件系统快照、启动后 ACL 竞争或其他程序对数据库的直接访问，也不替代备份与恢复验收。
