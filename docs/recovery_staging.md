# 隔离恢复候选与恢复副本

当前提供本机命令行和“数据与规则”页面的隔离候选准备、只读复核，以及将候选激活为**新路径数据库副本**的流程。激活不会覆盖当前数据库、修改服务默认配置或自动启动新副本。此流程仍不是完整的备份恢复验收：已实现检查的覆盖范围有限，目标环境兼容、全部业务合同和真实运行验收尚未完成。

## 准备隔离候选

```powershell
python -m dlt.recovery "源数据库路径" "新目录中的候选数据库.sqlite3"
```

目标目录须已存在，目标数据库及同名 `-wal`、`-shm`、`-journal` 不得存在。程序以只读方式读取源数据库，使用 SQLite 的备份接口复制同一读取快照，包括已提交但尚未检查点的 WAL 内容；在目标目录的临时文件上执行当前已实现的完整性检查。仅检查状态为 `passed` 时才发布：先对已关闭的候选文件调用 `fsync`，Windows 使用同目录、目标存在时会失败的重命名；其他系统使用同目录硬链接，避免覆盖已有文件。源数据库、已有目标及日志不被覆盖；不认识的数据表或触发器、缺少原文、检查失败、超过 512 MiB 上限均会阻止发布。目标文件系统和执行权限必须支持对应的同步与发布操作，否则保留源文件并报告失败。文件同步不等于目录项在突然断电后的持久性保证，也不替代目标文件系统和真实恢复验收。

输出 `status: prepared` 仅表示候选副本已发布且列举的部分结构、摘要和引用检查通过，**不表示完整业务合同、来源真实性或恢复可用性已核验**。该步骤不执行更新计划和研究任务；副本保留原库的计划启用状态及其他运行记录供审计，并新增持久隔离标记。本版应用服务、独立更新进程和自动计划检查入口遇到隔离标记会拒绝执行，包括标记表内容损坏或为空的情况。该保护依赖本版程序；旧版程序、其他 SQLite 工具或用户直接修改数据库不受此保护。候选复核通过后可按下文显式创建新的可运行副本；候选本身仍隔离，不能直接作为运行库。应在没有其他进程同时创建或操作目标及同名日志的隔离目录中使用。

本版的训练、历史回测和固定评估任务入口，以及对应的计算子进程也会拒绝隔离库；直接调用中断任务恢复入口时同样拒绝，不把留存的运行状态改写成失败。同步模型训练入口也受隔离标记保护。这些检查不限制其他 SQLite 工具或直接操作数据库，也不表示所有可调用函数均被隔离机制覆盖。

当前检查包含自动训练计划的状态事件、重试关联及固定训练输入、任务和模型产物的一致性；发现此类损坏时不会发布候选副本。检查覆盖范围仍有限，详见[数据完整性说明](data_integrity.md)。

实际组合评估的请求、结果、来源和组合关系也纳入检查；理论平均奖金及一等奖覆盖按固定子注和情景重新核算。若这些关系或数值不一致，候选副本不会发布。已记录的来源冲突本身不等于数据损坏：旧评估继续保留，其当前可用性仍需业务复核。本步骤不重放全部模拟开奖，也不证明其他业务对象已经完成全部恢复合同。

副本包含研究数据、用户留存的来源文件及可能存在的敏感内容，另含本机隔离标记；它不是脱敏导出，不能据此认定符合凭据和路径排除要求，也不要将其当作可分享的备份。可另行使用[口令加密数据库快照](encrypted_backup.md)保存数据库并准备隔离候选，但解密后的候选仍是明文。页面提供口令认证、内存检查、候选准备/复核和新路径激活。符合 PRD 的完整备份恢复验收、凭据隔离、全部引用/业务合同核验、目标环境兼容及真实运行验收仍未完成。

## 复核并激活为新副本

隔离候选可先通过当前已实现的只读检查复核，再激活到一个不存在的新数据库路径。命令行步骤、明文及原有计划确认项、失败时的保护行为见[口令加密数据库快照说明](encrypted_backup.md#将复核通过的隔离候选恢复为新的可运行数据库副本)。激活操作会再检查候选，先发布隔离的新副本，再移除新副本的隔离标记并复核；若复核失败会尝试重新隔离。当前数据库和隔离候选不会被覆盖。

只有在确认目标路径、运行环境和副本内容后，才以新路径明确启动服务；启动该副本时，原先启用的计划可能开始执行。使用项目 Python 环境，在项目目录执行：

```powershell
python -m dlt.app --db "D:/受保护目录/restored.sqlite3" --port 8766
```

这不会改动默认数据库路径或服务配置。需要回到原库时，停止该服务并重新用原数据库路径启动。启动命令可用不代表恢复已经通过完整验收；在完整业务、版本兼容、访问策略及运行验收完成前，副本状态仍应视为未完成正式恢复认证。

临时文件保存在目标目录。正常结束会删除临时名称；进程崩溃或清理失败时可能遗留以 `.dlt-recovery-` 开头的副本。若结果中的 `staging_cleanup` 为 `failed`，目标副本已发布，但临时文件可能仍存在；命令退出码为 3，应检查并安全处理目标目录。检查失败或无法发布时退出码为 2，不覆盖已有目标；若已完成检查，错误输出包含不回显记录内容或本机路径的检查结果。

2026-11-01 的本机测试中，工作区内的隔离目录通过了真实发布、包含未检查点 WAL 的复制和固定报告金额更正记录的读取核对；受限系统临时目录仍返回 `WinError 5`，不代表其他目录或文件系统均可发布。
