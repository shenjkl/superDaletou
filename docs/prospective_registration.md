# 前瞻研究登记：当前实现

`dlt/prospective.py` 保存研究者主动核对的规则、日历和税费原文、提取内容和核对备注，并将协议、固定副本清单以及每个候选/对照完整子注一起冻结。通过本机浏览器“前瞻实验”可保存核对资料、选择已有配对草稿，并单期登记或按固定版本逐期登记及查看记录；资料页面要求手工输入结构化 JSON，每份来源文件上限 5 MiB。可选的“从允许的官方 HTTPS 地址获取原件”会由本机服务通过同一官方主机白名单读取当前响应，拒绝重定向、非 identity 压缩、超时和超出 5 MiB 的文件；浏览器复核响应长度与 SHA-256 后把原件放入现有文件表单。该抓取没有持久业务副作用；用户仍须人工检查来源、适用期、原文和结构化 JSON，并明确确认后才能保存。HTTPS 主机、响应字节和摘要不能证明发布者身份、内容时效或规则适用性，资料仍标为本人核对且未独立认证。原件在提交前会连同请求输入保存到浏览器 IndexedDB，以支持待确认恢复；浏览器存储额度不足或严格持久写入不可用时，提交会在发送前失败。来源文件作为 Base64 经单独 8 MiB 上限的本机 JSON 路由发送，其他 JSON 写路由仍为 1 MiB 上限。它不调用购票服务。

## 结构化资料格式

以下仅为**合成测试格式**，数字、奖级、税费及网址均不能用于实际登记。实际资料的每个字段必须来自本人核对的、适用于目标期的原文。规则资料中的 `source` 必须与填写的来源网址完全一致，`verified: true` 只是本人声明已核对，不代表系统认证官方来源。组合生成页面可填写日历与规则版本引用，默认分别为 `manual-date-v1` 和 `manual-price-v1`；日历和规则资料的 `version` 需要与组合引用一致。填写版本本身不构成核验。

日历资料的结构：

```json
{"issue":"26017","draw_date":"2026-12-01","cutoff_at":"2026-12-01T20:00:00+08:00","version":"manual-date-v1"}
```

规则资料的结构：`hit_groups` 必须列全前区命中 0—5 个、后区命中 0—2 个的 18 种情况；未中奖以 `null` 表示。奖级和 `payout_sort_map` 必须与目标期公布的奖金字段及追加口径一致。

对于第 26014 期及以后，登记和每次纸面重算会额外校验 2026 规则结构：18 种命中结果的奖级代码、101/201/301/401/501/601/701/801/901 对应的公布奖项序号、一等奖/二等奖追加映射，以及基本投注 2 元和追加投注总价 3 元。税费字段还须符合彩票中奖现行口径：同一人、同一期、同一游戏合并，收入超过 10,000 元时按 20% 计算。结构不符会阻断登记或重算。此校验只防止结构化输入偏离已编码规则，不证明上传文件来自其标注网址，也不独立证明该规则适用于目标期；正式奖金仍按开奖记录公布的单注金额读取。活动派奖期的纸面结算仅在明确声明已核对活动规则、开奖活动标记、完整派奖金额及候选/对照票面分组全部通过时计算，否则阻断。适用口径见[税务总局公告](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5233840/content.html)及[个人所得税法](https://www.chinatax.gov.cn/n810219/n810744/n3752930/n3752974/c3970366/content.html)。

```json
{
  "version":"manual-price-v1", "source":"https://www.sporttery.cn/synthetic-test",
  "verified":true, "applicable_issues":["26017"], "promotion_policy":"excluded",
  "hit_groups":{"0,0":null,"0,1":null,"0,2":null,"1,0":null,"1,1":null,"1,2":null,
                "2,0":null,"2,1":null,"2,2":null,"3,0":null,"3,1":null,"3,2":null,
                "4,0":null,"4,1":null,"4,2":"second","5,0":null,"5,1":null,"5,2":"first"},
  "additional_groups":{"first":"first-extra","second":"second-extra"},
  "payout_sort_map":{"first":"101","first-extra":"201","second":"301","second-extra":"401"},
  "prices":{"base":"2","additional":"3"},
  "tax":{"unit":"same_person_same_issue_same_game","threshold":"10000","comparison":"gt","rate":"0.2","rounding":"down","quantum":"0.01"}
}
```

税费资料的 `tax` 必须与规则资料完全一致，适用奖期也必须包含目标期：

```json
{"applicable_issues":["26017"],"tax":{"unit":"same_person_same_issue_same_game","threshold":"10000","comparison":"gt","rate":"0.2","rounding":"down","quantum":"0.01"}}
```

以上仅说明接口结构；样例故意不覆盖实际奖级，不能直接用于生产结算。来源复核路由的 HTTP JSON 请求上限为 8 MiB，以接收最多 5 MiB 原件的 Base64 编码和结构化元数据；其他 JSON 写入路由上限为 1 MiB。原文及完整重试请求先持久保存到浏览器 IndexedDB，超出浏览器实际存储配额时不会发送。

登记要求：固定假设、税后净收益配对差额、观察期清单、每个副本与组合包的对应关系、明确的副本聚合方式、排除与选择规则、内部截止，以及个人核对过的规则、日历和税费资料。每个候选或对照包是独立替代情景，并明确假定没有其他同一期同一游戏的中奖收入；如实际另有中奖，纸面税后结果不代表实际税额。当前实现支持的聚合是 `arithmetic_mean_v1`，时间证明等级是 `local_clock`；其他选择不会静默降级。

`tax.unit` 必须明确为 `same_person_same_issue_same_game`，表示当前程序仅支持同一人、同一期、同一游戏中奖收入合并的计算单位；此值只表明本人选择的计算口径，不证明官方规则适用。若实际适用单位不同或无法核验，不能登记或发布有效纸面收益。历史上未留该字段的实验及结果会保留，但当前状态标为待复核；可核对后分别补充新的规则、税费资料并登记更正，按现有更正流程重新计算，不能直接修改旧记录。

冻结时检查配对结构、成本、版本和来源依赖，检查所有副本使用同一方法与配置且种子、组合包不重复；目标期结果已进入本地库、日期不符、来源冲突、规则缺项、价格不符、截止已到或时钟回拨均拒绝登记。截止检查在数据库写入事务内重新执行。冻结后内容不可原位修改，同一请求键重复提交返回原记录；关闭实验只追加关闭记录，已固定内容保留。

核对材料的来源网址和原始字节会留存并计算摘要，但程序不会独立确认手动上传材料确由该网址发布。可选的本机抓取只将允许域名的 HTTPS 当前响应放入同一人工核对表单，也不认证发布者、适用期或发布时间；系统时间也不是第三方时间戳。因此结果明确标记为“本人核对资料、本地时间留存”，不能声称独立认证。正式使用仍需逐期核对具体官方日历、规则、税费和派奖，并解决网络来源认证。

更新成功后后台会检查已冻结实验：满足来源观察、号码、奖金、规则和税费核验的记录，会分别计算候选与对照并原子保存结果组。计算使用公布的单注奖金，假定纸面组合没有改变实际中奖人数、分奖或限额。若开奖或奖金有冲突，当前结果转为待复核；个人核对后选择版本，再重算并追加更正发布记录，旧结果不删除。缺奖项或规则映射时阻断。第 26050—26066 期只有在开奖记录明确标记活动、具备完整派奖奖级金额，核对规则声明 `official_draw_fields_and_ticket_group_threshold`，且候选和对照均保存有效的票面分组时才结算派奖；旧组合缺少分组会阻断，不推定中奖资格。单票 18 元门槛及 2 万/3 万元限额按留存分组和票价假设计算，不能证明实际出票或实际派奖资格。结果仍是本地核对情景，不能宣称官方认证；[税务部门公布的电脑彩票计税口径](https://jiangsu.chinatax.gov.cn/art/2025/8/14/art_16876_5501.html)应按适用期核验。

## 开奖版本复核与结果历史

在“数据与规则”中，出现“查看差异”的奖期可以展开各版本的日期、号码、派奖标记、奖金字段、完整原始字段及每条快照的来源观察。来源网址格式和留存数据摘要检查不构成独立来源认证。核对后选择具体快照，填写原因并明确确认；系统在保存时核对版本集合与所选行摘要，如果查看后出现新版本，必须重新查看，不能用旧页面代替对新增版本的复核。

保存选择后，系统尝试重新计算该奖期的本机固定实验，并分别显示完成、阻断或异常；来源、奖金或规则不满足要求时仍保留阻断，不能填零。异常在可能时写入实验检查记录，记录无法保存时页面会指出。条件恢复后可在同一复核区重试，重复计算不会重复发布相同结果；版本集合再次变化时原选择失效，需要重新复核。前瞻实验详情中的“查看结果历史”列出旧结果、新结果及检查记录。旧结果保留，依赖待复核期间不会被标为当前采用。此选择只控制本期纸面计算，不自动解除训练、回测或其他评估对冲突数据的限制。

## 日历、规则和税费资料更正

在“前瞻实验”先保存本人核对的新资料，再于“日历、规则与税费更正”选择同类型的现用资料与替代资料。页面列出提取字段差异、来源网址及留存原文摘要，用户填写原因并确认后保存更正。原文原样保留在本机数据库；由于文件可能包含凭据或本机路径，应用暂不提供原文件下载。在“已保存资料”中可查看通过摘要核验的 UTF-8 文本，每段最多 20,000 个字符，按纯文本显示；也可逐页查看 PDF 的本地图像预览，不会把原始 PDF 返回给页面。PDF 预览需要安装项目依赖，最多 200 页；每次使用独立进程，时限 10 秒、进程内存上限 768 MiB、预览图长边不超过 1,400 像素且 PNG 不超过 2 MiB；加密、损坏或超限文件会停止预览。PNG/JPEG 图片会在独立解码进程中按显示方向重绘并清除元数据，再作为单页 PNG 预览；文件最多 5 MiB、20 MP，输出长边最多 1,400 像素且 PNG 不超过 2 MiB。PDF 和图片预览都不是脱敏内容，原文中的敏感信息仍可能显示；压缩文件、其他图像/文档格式及非 UTF-8 文本不支持查看，应用也不能取回原始文件副本。还可以选择本人另行保存的原文件，在浏览器本地计算 SHA-256 并与留存摘要比对，该比对不上传文件；摘要一致只说明内容相同，不证明材料确由该网址发布。

规则和税费更正可选择作用于所有引用旧资料的奖期，或只作用于指定的一个奖期。指定奖期时，新旧资料的适用期清单都必须包含该期；该期所有依赖旧资料的固定实验都会受影响，其他期继续引用各自有效的资料。不同奖期可为同一旧资料登记不同替代版本；连续更正按全局和对应期的更正链查找有效版本，不允许在同一链节点登记互相冲突的分支。当前一次只能指定一个奖期，不支持按期范围或部分实验筛选。

保存后，范围内依赖旧资料的现有结果立即转为待复核，原实验、资料和结果历史保留；系统使用持久任务逐项尝试重算，展示完成、阻断、等待或异常。新资料不适用于目标期、价格不符或规则与税费不一致时保持阻断；调整到一致后可重试。重复执行相同输入不会重复发布结果。

日历更正只接受同一奖期的新资料，截止时间（北京时间）须与开奖日期在同一天。系统重新检查每个固定实验的登记时间：若登记时间早于新截止且固定方案目标日期不变，已发布结果先转待复核，再使用新资料和满足新截止的开奖后观察重新计算；新观察尚未取得时保持阻断。若登记时间等于或晚于新截止，或开奖日期与已固定方案的目标日期不一致，则不能将该结果视为有效前瞻，保留原实验及历史结果并标为待复核。系统不自动调整号码或补造截止前记录。

已保存的待处理任务会在本地服务运行时恢复，处理进程中断后由有效执行者接管；失败的任务可在页面重试。该机制不会自动发现外部资料更正，必须由本人核对后登记。新实验须选择该目标期有效的资料。引用旧日历的自动训练计划会阻断；已经提交的训练任务可能继续结束，但不能仅凭训练完成认定符合新日历。因该计划不可修改，继续研究需为尚未开奖的期另建实验版本和计划；已完成的训练记录保留，不自动变成新日历下的合格登记。

## 多奖期实验版本

在“前瞻实验”的“多奖期实验版本”中，先选择首期配对草稿及本人核对的首期日历，按计划顺序输入未来观察期、填写假设及规则、选择副本数量，然后生成预览。首期第一个副本使用模板种子，其他种子由浏览器生成；确认后观察范围、副本名单、每期种子及方法配置被固定。系统不根据期号推断开奖日；各类方法均可针对单期另行设置自动生成和登记。

新实验版本中，每个奖期、副本的预定生成种子必须是 0 至 4294967295 的整数，与当前方案生成器支持的范围一致；同一期副本不能使用相同种子。某些旧版本曾允许更大的种子，这些历史协议原样保留并可幂等查询，但无法按该种子生成相应配对。页面列出受影响奖期；如继续研究，应为尚未开奖的奖期另建版本，不能修改原协议或补造已开奖的前瞻记录。生成器派生出的候选和对照内部随机种子可为 64 位，它们不是此处的预定生成种子。

页面列出每期预定种子。可以在截止前手动用相应种子和固定方法生成配对草稿，再进入实验版本“登记奖期”选择每个副本和本人核对的资料；也可以分别确认各期自动登记计划。系统检查固定的副本、种子、预算、结构、方法配置、生成代码摘要、生成版本和 Python 运行时。固定模型方式要求各期使用同一模型产物；逐期重训方式要求各期分别使用符合固定训练规则的模型，同期副本使用同一产物。历史快照、目标日期及适用规则引用可随奖期变化，但每期必须分别通过登记校验。固定及关联同一事务完成；同一版本同一奖期不能重复登记。

### 逐期重训的固定规则

可在模型训练时填写“滚动训练目标期”，以已完成的树模型或 LSTM 任务生成首期配对，并在多奖期版本中选择逐期重训。预览从首期产物固定训练历史长度、验证期数、模型窗口、参数、训练种子、代码和运行环境；固定前会再次核验模板。每个目标期须分别训练绑定该期的任务，再使用该期产物生成各副本。训练可以手动提交，也可以由用户为该期明确创建后台训练计划；另行确认自动登记计划后，系统才会生成配对并尝试登记。

登记前，系统核对目标期训练任务在配对创建前完成，所选快照在训练开始前已有本机观察记录；模型的固定参数、种子和版本不变，训练历史长度及验证期数符合协议，模型和配对的历史截止一致。整个训练窗口须分别覆盖训练开始时和配对生成时本机已观察的最近若干期；若期间出现更新的历史期，需要重新训练。最近窗口中有多个不同奖期但日期相同时，现有数据无法确定先后，系统阻断而不推测顺序。目标期已出现在本机数据时，不能新建该期训练；如训练期间目标结果出现，则不发布该任务产物。依赖出现冲突时标记待复核，已固定历史不覆盖。

“最新”仅以本机留存的观察时间与号码为依据，不能证明外部来源完整、官方公布时间或本机时钟可信。历史缺期、日历及奖金规则仍须本人核对；不能据此声称严格时点重放、独立评估或策略有效。

### 逐期自动训练计划

在已固定的逐期重训实验版本中选择“设置自动训练”，指定目标期、本人核对的该期日历、预期最近历史截止期、最早开始时间和训练时限，确认后创建计划。每个版本的同一目标期只能创建一个不可更改的计划；填写错误或取消后不能覆盖原计划，需要为后续尚未开奖的期另建实验版本。计划创建本身即授权该期训练，未创建计划的奖期不会自动训练。

本机浏览器服务运行时，后台等待计划开始时间和预期历史数据；检查固定代码、环境、快照、窗口、目标期与截止时间，通过后提交真实训练。任务完成时再次核对训练开始和完成时已观察的历史窗口；期间历史窗口变化则阻断并保留记录。训练完成只表示本次任务完成，生成配对前和登记时仍要再次核对，不能将任务状态当成有效前瞻结果。若本地数据缺失、同日奖期顺序不明、目标期已出现或已到截止时间，计划等待或阻断并显示原因；不会在截止后补造训练或登记。

页面显示计划状态及事件，可以取消；失败或阻断后须明确重试，重试使用新任务并保留原任务记录，最多重试 9 次。关闭浏览器后，本机服务仍运行时训练检查继续；关闭服务、休眠或关机时不执行，恢复启动后重新检查已保存计划，错过截止时间的计划会阻断。没有开机自启；仅运行 `dlt.worker` 的独立开奖更新进程不会执行自动训练计划。计划不证明本机数据来源、完整性或本机时钟可信。

### 训练后自动生成和登记

训练计划创建后，可在其条目选择“设置训练后自动登记”，为这一期选择本人核对的规则、税费和内部登记截止并明确确认。内部截止不得晚于已选日历的截止。此授权只适用于该训练计划的一期，不会为其他奖期自动创建计划；不需要自动登记时，仍可手动生成和登记。

本机服务检查到训练计划合格完成后，使用固定实验版本中的全部副本、种子、方法配置及该期训练产物生成候选和对照，并重新核验来源、训练窗口、截止及目标期，再固定为纸面实验。生成期间可以取消；即使已有部分配对草稿，未通过最终检查时也不会固定实验。固定实验和自动登记计划完成状态在同一事务保存；进程中断后，等待中的计划可重用已保存的相同草稿继续执行。计划阻断或失败后需明确重试；规则或税费更正后，可按新资料另建登记计划，旧计划保留。同一训练计划同时最多有一个等待中或已完成的自动登记计划。

关闭浏览器不影响正在运行的本机服务，服务停止、关机或休眠期间不执行；恢复后如已到截止或目标开奖结果已出现则阻断，不补造前瞻登记。本人留存的来源和本机时间不构成独立认证。

### 固定模型或无需训练方法的自动登记

在对应实验版本选择“设置自动登记”，逐期选择本人核对的日历、规则和税费，填写预期历史截止期、历史窗口长度、最早开始时间和内部登记截止并确认。该计划支持随机、冷热号、固定树模型及固定 LSTM；固定模型沿用实验版本原产物，不重新训练。历史窗口长度不得小于方案方法或模型所需的窗口。

到开始时间后，系统查找本机已观察到、截至预期奖期的最近历史窗口，并选择覆盖该窗口的快照。数据尚不足时等待；出现更新的历史期、号码或日期冲突、同日奖期顺序不明时阻断。选定快照和窗口摘要后保持不变；每个副本生成前及固定登记事务内再次检查，确保未因新观察而静默改变输入。完成状态和固定实验同一事务保存；中断后可重用已生成的草稿继续。取消、迟到、目标期开奖或资料更正时不发布新登记。

计划只检查本机已有观察，不能证明官方数据无缺期或提供可信时间。每一期须单独确认，服务关闭或电脑休眠期间不运行；仅独立开奖更新进程不会执行此计划。失败、阻断可在条件恢复后重试；需要更改已固定的资料、历史范围或时间时，应重新确认新计划，旧记录保留。

关闭实验版本后禁止追加奖期，已登记的期仍按原流程计算、更正及保留历史。同一提交键重发返回原记录；改变协议或尝试关联其他版本会被拒绝。当前支持预先列出最多 200 期、页面最多 10 个副本，接口最多 100 个副本；不支持动态扩展已固定观察范围。

在实验版本或“证据结论”中展开“查看跨期描述结果”，可查看计划、可计入和缺口奖期数，以及每期登记、等待、阻断、待复核或未登记状态。系统校验预定副本清单与金额，先计算每期各副本的税后净收益配对差额的算术平均，再按可计入的独立奖期等权计算跨期平均。没有可计入奖期时显示“暂无”，未完成的奖期不填零；部分结果明确标为部分，并列出全部计划奖期。页面展开时定期重新读取，无法刷新时不继续显示旧数值；页面展示检查时点，结果可能在此后随资料更新而变化。

“查看候选与对照的成本和收益”分别列出每期副本平均后累计的成本、税前奖金、税费和税后净收益，以及累计净收益除以累计成本。成本为零时 ROI 不适用。中奖情景指某副本税前奖金大于零，盈利情景指该副本税后净收益大于零；先计算每期符合条件的副本比例，再对可计入奖期等权平均。它们是替代情景的描述，不是实际购买、到账金额，也不等于未来中奖概率。

净收益 P25、P50 和 P75 以每期的副本平均净收益为样本，采用最近秩法（排序后取 `ceil(p × 有效奖期数)` 位）；样本少时多个分位数可能相同，它们不是置信区间。单期最大奖金占比以该期副本平均税前奖金除以各可计入期的副本平均税前奖金之和；并列时使用计划顺序最靠前的期，无奖金时不适用。

汇总保留精确分数计算，金额和百分比仅展示时四舍五入至两位。规则或开奖更正未完成重算时，受影响期转为待复核并移出当前统计，原历史仍可查看。来源及时间仍是本人留存，**这些都是描述性结果，没有经审核的推断区间，也不会产生采用或购买结论**；多个副本不算作多个独立奖期。统计推断仍未实现。

跨期配对差额的实际观察范围、分位数和逐期移除敏感性可用于理解少数奖期对均值的影响；口径、缺口处理及不能将其解释为置信区间的原因见[配对差额说明](paired_description.md)。

当前尚无第三方时间证明。开奖版本比较展示本地留存的信息，并不自动核对外部原文。受限沙箱内网络接口曾无法直连；沙箱外已验证官方接口单页抓取，真实开奖后的前瞻自动计算仍未验证。测试中的规则、文件与号码均为合成数据，不代表真实的彩票规则或结果。
