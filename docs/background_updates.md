# 本机开奖数据更新：当前实现边界与操作

本机浏览器服务启动时同时运行后台检查线程，抓取体彩历史开奖接口的最新一页并留存原始响应和快照。已登记且早于最新页的目标期缺少合格本地观察时，在页数上限内继续抓取历史页。成功更新后会检查已固定的本地前瞻实验；资料齐备且无冲突时计算纸面结果，否则记录阻断原因。它不会购票或自动固定实验。中奖奖金、规则、日历与税费需要另行核验；抓取时刻不是历史发布时间。

2026-10-30 在沙箱外只读访问官方接口成功，并用临时数据库验证启用的计划自动抓取、保存快照和写入运行记录；响应最新期为 26123。该次数据库中无前瞻实验，后续计算检查为跳过，不能视为真实自动结算已验证。受限沙箱内直连曾失败，实际可用性取决于运行环境和网络。

## 计划配置

可在本机浏览器的“数据与规则”中创建、编辑、启用或暂停计划并查看最近运行；创建时必须填写全部字段，计划默认暂停。编辑前须暂停计划并等待已有运行结束，保存后仍保持暂停；若配置已被其他操作改变，页面须重新加载后再提交。每次修改原子保留修改前后配置和本机时间；新运行记录其配置，页面可查看最近运行配置及配置变更。较早版本的运行若没有留存配置快照，会明确显示缺失，不用当前配置冒充历史参数。

当本机服务连接或数据读取失败时，页面显示连接状态无法确认，隐藏上次读取的计划列表、更新线程状态、开机启动状态和本机快照；当前页面中正在编辑的计划输入保留，暂停提交。连接恢复后需重新读取快照和计划状态，核验完成后才重新显示和允许提交。页面会自动重试连接；未提交内容只保留在当前页面会话，刷新或关闭页面不保证保留。历史回测和训练页面的部分当前状态也已增加断连遮罩；覆盖范围和限制见[范围核对说明](holdout_audit.md)。该处理不代表其他页面或写入结果待确认流程已经完成验收。

编辑保存后，下次计划时间重设为新起点；本人再次启用时，如果起点已过，则合并漏掉的周期并执行一次补查。一次性补查不支持编辑。页面显示本机服务的更新线程状态、最近检查时间及错误，并可选择查看已保存快照的最近 12 期、来源记录、号码与奖金资格和版本冲突。也可使用下方命令行管理并运行计划：独立更新进程和本机服务的更新线程使用同一执行锁，避免重复运行；当独立进程占锁时页面提示等待。既有研究快照表单独标为静态，不代表实时抓取结果。

计划旁的“立即补查”按该计划的来源、超时和重试设置建立一次性持久任务，不改变原计划的启停状态和下次时间。后台线程可运行时执行；若执行过程中异常退出，下次启动按执行权恢复。一次性任务不会按周期重复，运行及后续纸面检查状态分别保留。

运行中的周期更新或一次性补查可选择“取消本次运行”，与暂停周期计划是两个独立操作。系统先显示“取消中”并阻止该运行后续写入；正在执行的网络请求不会立即被强制终止，需等待返回或配置的超时，之后显示“已取消”。重试等待期间会尽快响应取消。如果取消前某一页快照已经完整提交，该快照保留；取消的运行不发布成功状态，也不触发该次运行的后续纸面检查。取消不会更改周期计划启停状态，已启用计划仍可在下一次到期运行；若希望之后也不运行，须另行暂停。

取消与完成竞争时，以先提交的运行状态为准：先完成则保留成功结果，先接受取消则迟到结果不能改为成功。如果后台进程在取消中断开，执行权到期后会将原运行标记为已取消；一次性任务不会因此自动重跑。跨页更新已经保存的页也会保留，不能把“已取消”理解为回滚所有已经提交的数据。

命令行创建需要准备 UTF-8 JSON 文件。以下数值仅说明格式，实际频率与限制由使用者自行决定：

```json
{
  "start_at": "2026-11-01T20:00:00+08:00",
  "interval_seconds": 3600,
  "timezone_offset_minutes": 480,
  "page_size": 20,
  "max_pages": 10,
  "timeout_seconds": 20,
  "max_bytes": 1048576,
  "retry_count": 2,
  "retry_wait_seconds": 30
}
```

计划以 `start_at` 为基准按固定秒数重复，时间存储为 UTC；`timezone_offset_minutes` 是显示时的固定偏移，不是可处理夏令时的时区数据库。`max_pages` 包含最新页，可设 1—1000；旧计划缺省为 10 页，达到上限仍未找到时显示未完成。系统将最近一次完成运行的末页及目标摘要记入运行记录；下一次周期或该计划的手动补查先重新抓取并核对末页，再向后推进。查询目标、页内容或顺序变化时重新从前面核对。因为最新页和锚点页也占用额度，持续推进通常要求上限至少为 3 页；上限为 1 或 2 时可暂停并编辑计划，提高上限后重新启用。只对缺少合格本地观察、且日期早于最新页的已登记奖期追查，不能断言其他历史数据完整。间隔、大小和重试受实现边界校验；每页最多保留 5 MiB。每次页面请求由子进程执行并受到整体时限约束。

从项目目录运行，以下 `python` 应指向具备 Python 3.12 或兼容版本的解释器：

```powershell
python -m dlt.worker --db <数据库路径> create --config <配置文件路径>
python -m dlt.worker --db <数据库路径> status
python -m dlt.worker --db <数据库路径> enable <计划ID>
python -m dlt.worker --db <数据库路径> run
python -m dlt.worker --db <数据库路径> pause <计划ID>
```

创建计划时始终暂停；用户需明确启用。关闭浏览器不会停止本机服务或其后台线程，但终止服务、关机或休眠后不会继续运行。服务或独立进程再次启动后会合并漏掉的轮询并补查一次；未创建计划或全部暂停时不会联网。

“数据与规则”的 Windows 登录后启动设置默认关闭，只有本人点击开启后，才会写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 启动项；关闭会删除与当前服务实例匹配的启动项，不改变更新计划本身的启停状态。登录该 Windows 用户后才尝试启动；未登录、休眠或关机时不执行，Windows 可能延迟启动。该设置不是 Windows 系统服务，也不保证登录后启动一定成功。服务实际运行和更新情况仍以页面中的后台状态及运行记录为准。

启动项使用当前 Python 环境的 `pythonw.exe`、项目启动文件、当前数据库和端口；项目、环境或数据库移动后需要重新检查设置。若同名启动项属于其他配置，页面提示冲突，不会覆盖或删除；缺少启动程序、命令超过 Windows 限制或权限不足时不能启用。此能力目前通过模拟注册表和无套接字测试验证；尚未实际写入注册表或通过 Windows 注销、重启和登录验证。参见 [Microsoft 的 Run 注册表项说明](https://learn.microsoft.com/zh-cn/windows/win32/setupapi/run-and-runonce-registry-keys)。

上述是开奖更新计划。逐期重训可以另行创建每期自动训练计划，由本机浏览器服务中的独立后台线程执行；单独运行 `dlt.worker` 只处理开奖更新，不执行训练计划。训练计划的固定条件、截止规则及手动登记边界见[前瞻研究登记说明](prospective_registration.md)。

## 恢复与核验

- 每个计划同一时刻只有一个有效执行权；过期执行器即使迟到返回也不能写入。
- 运行记录保留每次尝试、失败原因与成功快照 ID；重试耗尽只结束该次运行，不自动禁用计划。
- 如果进程在导入快照后、写入运行终态前中断，恢复时可能再次请求；快照按内容去重，原始观察记录仍保留。
- 更新成功后若进程中断，恢复时补做未处理的纸面计算；计算失败与数据抓取成功分别记录。
- 每次成功更新后，除优先检查新快照外，也会按观察时间检查本机留存的其他含目标期快照；若新快照无法通过来源/时点校验，会继续核对其他候选。每个候选仍须通过原有官方地址格式、留存字节、登记与截止时间、规则及冲突校验；无合格来源时不会计算。已有有效结果不会重复生成，资料冲突仍需复核。
- 若过了登记截止时间仍无包含目标期的本地快照，后续检查标为未完成，并列出尚未查到的期号；这并不证明该期已经开奖。单个实验记录损坏会标明检查异常，不阻止其他实验检查。下一次成功更新会再次检查这些未完成项。
- 历史分页发生重复期号、日期倒序异常、请求失败、返回不足请求期数或达到上限时，最新页仍可用于后续检查，但运行记录显示历史补查未完成及原因。每页保存原始响应；同一已登记目标期的结果仍须通过来源和时间校验。锚点通过留存原文、页码与开奖投影核对，只用于定位下次查询，不证明两次运行之间列表没有发生其他变化；到达接口页码上限或疑似末页仍未找到时会从前面重查。跨页过程尚未经过真实官方接口及浏览器端到端验收，分页结果不能证明历史数据完整。
- 页面将抓取状态与后续纸面检查分别显示；即使抓取成功，也可能因某个实验缺少奖金或规则而阻断该实验的计算。
- 不同来源出现冲突时，当前结果转为待复核；个人选择版本并重新计算之前，不把旧结果当成当前有效值。当前处置仅有程序接口；派奖及缺少规则映射会阻断。
