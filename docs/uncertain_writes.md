# 写入结果待确认：个人判断服务端基础

本机服务已为“保存个人判断”和“保存关联新假设草稿”提供按请求标识核对及封止的服务端能力。证据页已接入 IndexedDB 待确认索引、查询、封止、关联重试和显式确认；服务端另以对象占用避免不同客户端使用新请求标识并发提交同一对象。其他页面的写入操作尚未全部接入，因此这不是 PRD R52 的完整实现。当前实现及验收边界见[协调设计](uncertain_write_coordination.md)。

两类操作分别使用 `decision` 和 `draft`。请求摘要是对应业务请求经服务端校验、去除首尾空白后的规范 JSON（键排序、紧凑分隔符、UTF-8）之 SHA-256，不包含 `request_key`。个人判断的摘要对象包含 `kind`、`key`、`choice`、`reason`、`limitations`、`evidence_sha256`；新假设草稿的摘要对象包含 `decision_key`、`hypothesis`。摘要可用于检查相同标识是否指向同一输入，但不是加密，低熵输入仍可能被猜测。新增的服务端准备入口计算摘要，后续页面无需自行模仿 Python 的空白字符规范化。

- `GET /api/research-writes/status` 接受 `operation`、`request_key`、`request_sha256`，需本机会话；返回 `committed`、`fenced` 或 `unknown`。`unknown` 仅表示本次查询尚未发现结果，原请求仍可能在途。
- `POST /api/research-writes/fence` 使用同一组字段，要求本机同源会话与 CSRF 校验。它和这两类实际保存使用同一个 SQLite 写事务锁：若保存已经提交，返回原结果；若尚未提交，持久化封止，之后原请求不能提交。重复封止同一标识和摘要返回相同记录；摘要不匹配时拒绝。
- 封止记录不可通过应用正常修改或删除，数据库插入触发器也阻止已封止标识写入两张业务表。完整性检查核对封止结构、触发器和冲突记录；隔离恢复副本保留封止并保持不可执行。数据库持有人使用外部工具修改文件或删除保护不属于这些应用保护所能阻止的范围。

`POST /api/research-writes/prepare` 接受操作类型、请求标识、完整业务请求以及可选的 `retry_of`，由服务端规范化、计算摘要并在本数据库记录不可修改的准备记录；准备本身不保存判断或新假设。相同请求重复准备返回相同记录；同一标识不同输入被拒绝。个人判断及草稿的 HTTP 保存必须带 `require_intent: true`，状态查询带 `require_intent=1`，封止也必须匹配准备摘要；其他数据库不存在匹配准备记录时拒绝。服务端按对象拒绝竞争请求，并在已提交或已封止结果经用户确认前保持占用。

- `GET /api/research-writes/current` 按操作及对象发现占用；只返回请求标识、摘要、终态和占用版本，不返回未提交的理由或假设正文。
- `POST /api/research-writes/acknowledge` 要求请求摘要、终态与当前占用版本匹配；它追加确认记录并释放占用。迟到的旧请求不能释放已转移给重试请求的占用。

主动重试可在新准备记录的 `retry_of` 中关联原请求；原请求必须属于相同操作和对象，并已封止。同一原请求只能准备一个直接重试；如该重试后来同样无法确认，应先核对和封止该次，再关联它创建后续重试。准备记录只包含操作、请求和对象标识、摘要、重试关联及本机时间，不含判断理由、新假设正文、凭据或会话令牌。完整性检查会核验准备记录、已提交内容和重试关联。

严格模式可以识别没有该准备记录的另一份数据库；它不能单独区分在准备后复制出的数据库或被手动回滚到较早时点的副本。项目的隔离恢复流程目前不会启用候选，完整恢复切换和版本连续性机制仍待实现。页面接入时不得把手动替换或回滚数据库后的查无结果解释为原数据库肯定未提交。

证据页现已在提交前将待确认索引和恢复输入写入本机 IndexedDB，并使用 Web Locks 协调同源标签页；存储不可靠时不发送。浏览器关闭后可按原请求恢复查询；状态未知时可封止，只有明确确认已提交/已封止后才清除本机副本。封止后的主动重试使用新请求标识并关联原请求，重新通过业务证据校验。Web Locks 本身只覆盖同一浏览器和来源，跨浏览器由服务端对象占用协调。相关流程详见[协调设计](uncertain_write_coordination.md)，真实浏览器和 HTTP 故障注入尚未验收。

本机索引与恢复输入分库存于两个 IndexedDB object store，并以同一严格持久事务更新：准备阶段保留同一请求标识及原输入以便重复准备；发送前先把状态持久化为已发送；提交结果未知时查询或封止，不盲目重发。封止后的显式重试生成新标识并关联原请求。重新打开页面后会重新向当前服务核验已提交或已封止记录；用户确认后服务端释放对象占用，客户端才删除本机副本。页面已说明暂存内容留在本机浏览器中及确认/清理后的边界。

浏览器锁只覆盖**同一浏览器、同一来源**的协作页面，不能单独协调不同浏览器、不同端口来源或绕过页面直接调用的客户端。个人判断/草稿写入已由服务端对象级占用覆盖这些客户端；其他模块写入尚未统一接入，不能把当前保护表述为全站去重。

具体事务合同、已实现边界和未完成验收见[跨客户端协调设计](uncertain_write_coordination.md)。
