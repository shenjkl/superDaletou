## 尚需完成的验收与范围核实

所有待确认日志所用的 JSON 提交及封止 POST（含方案生成/评估、纸面复核/重算和恢复文件路由）统一经写入客户端处理；无法解析的响应体及 HTTP 5xx 会标记为连接/结果待核实状态，持久待确认索引保留原请求，不把响应歧义当成明确失败。口令加密快照下载仍使用二进制响应专用路径；它不创建待确认索引且不写持久业务台账。此处理只解决响应体或服务端错误的歧义提示，真实丢包、后端事务提交点、刷新与重启行为仍需按 AC76—AC79 实测。

组合生成与收益评估的服务端封止和关联重试已补齐源码接入。当前 POST 路由静态追踪另确认以下入口只做只读读取或临时计算：`/api/holdout-audit` 使用只读 SQLite 连接及 `query_only`；`/api/source-review-preview` 从只读连接读取已存资料，文本分页在内存执行，PDF 子进程只返回受限 PNG 字节；`/api/source-review-capture` 只从白名单 HTTPS 主机读取有大小/时限限制的原件并返回内容摘要，不写入业务数据库；`/api/generation-replay`、`/api/paper-replay` 及 `/api/experiment-series/rolling-preview` 在只读事务内核验并于内存组装结果；`/api/encrypted-backup/inspect`、`/verify-candidate`、`/verify-restored-copy` 只读验证输入文件或数据库。这些入口当前没有持久业务写副作用，无须纳入待确认写入日志。剩余重点是 AC76—AC79 的真实浏览器/HTTP/并发/重启验收；在完成这些验收前，不据此宣称 R52 整体完成。

逐路由复核（2026-11-04）发现 `/api/source-corrections/retry` 会推进持久 follow-up，已接入纸面写入回执合同：请求键、摘要、`correction_id` 与 scope 写入不可变回执；重试与封止共用 SQLite 写事务；回执落盘时将 follow-up 排回 pending，进程中断后可由既有启动恢复扫描领取；同键重放不会再创建新请求，状态接口补充当前 follow-up。浏览器前瞻页复用 IndexedDB、Web Locks 查询/继续/封止/核实后清理；原请求封止后仅可关联同内容重试，已知计算失败可发起新的显式命令。当前只有源码和语法检查，真实 HTTP、浏览器、丢响应、封止竞争与服务重启仍未验收。

只读、临时计算或文件导出入口须先确认是否产生持久业务副作用；不能仅因使用 POST 就强行套用写入日志。上述入口已完成源码边界核实；若将来改为持久化审计记录、生成服务器文件或更新业务状态，须重新纳入写入盘点。

## 接入顺序与验收

1. 前瞻实验/系列关闭已完成代码接入；固定评估和排除范围也已有请求恢复实现。三类都仍需真实链路验收：证明原请求查询、封止与提交竞争只有一个结果，重复提交不重复产生业务记录。
2. 完成 P1 的来源和开奖记录操作，重点处理大文件索引、原始字节摘要、后续重算任务关联及部分失败状态。
3. 完成计划任务和其他生成/评估入口，并标明“请求已受理”和“后台任务完成”的不同状态；系列创建已接入源码，仍需真实链路验收。
4. 每类入口补齐 AC76—AC79 的故障路径：成功响应丢失、查询暂时未知、刷新/重启恢复、封止胜出、提交胜出、同键不同内容、同对象不同键并发、局部计算失败。
5. 汇总逐入口追踪表后再判断 R52 是否完成。VM 模拟、单元测试或本机哈希不能替代真实 HTTP 与浏览器验收。

## 固定历史评估写入增量（2026-11-03）

固定协议、启动运行、创建关联版本和金额重算现在均在浏览器发送前写入独立 IndexedDB 日志，带操作类型、原请求键及规范化输入摘要，并使用 Web Locks 协调同一请求的多标签页操作。页面可按原键查询、继续、封止和关联相同操作与内容的重试；未知状态保留原请求，终态经服务端核验后才可清理本机副本。协议和运行/更正业务记录与接受回执在同一 SQLite 写事务内提交；服务端封止与迟到写入互斥。金额重算的幂等键绑定到原固定范围，运行启动回执关联到具体尝试。

完整性检查核对请求摘要、规范化输入、不可变回执/封止/重试链及其与固定协议、运行尝试、更正记录或关联范围的引用。请求级幂等仅解决不确定写入的恢复；失败后的研究运行重试仍须按原运行规则生成新命令，不能把“HTTP 请求已受理”误当成后台任务完成。

此次只做源码静态审阅；未新增或运行自动化用例，未启动服务或浏览器。未验证真实 IndexedDB 严格持久写入、Web Locks、HTTP 响应丢失、封止/提交并发、刷新和服务重启恢复；也未覆盖直接数据库写入或旧版外部客户端。因此 AC76—AC79 与 R52 仍未验收通过。

## 滚动训练计划创建请求回执增量（2026-11-03）

随后，前瞻页创建/取消/重试入口均增加严格持久 IndexedDB 暂存、Web Locks 同对象串行、原键状态查询/继续及核实后清理。服务端回执与各自状态变更同事务保存；封止接口与写入口共用 SQLite 写锁，封止后拒绝原键迟到写入；同内容关联重试受限为已封止原请求的一次直接重试。取消请求重放会继续对关联训练任务发出幂等取消。

未新增或运行自动化测试，未执行真实 HTTP、浏览器、响应丢失、封止竞争、并发及重启验收；登记计划家族仍未接入，不得据此认定 R52 已完成。

## 滚动登记计划创建请求回执增量（2026-11-03）

滚动登记计划现增加服务端事务封止和一次性同内容关联重试，页面复用待确认日志。静态登记计划创建/取消/重试现接入 IndexedDB 待确认日志、按键查询/继续/封止和关联同内容重试；服务端在 SQLite 写锁内协调提交与封止，并以唯一直接重试链约束关联操作。完整性检查现验证静态登记回执与业务计划、接受/封止互斥及重试链。仅做源码编译检查，未运行自动化测试、HTTP、浏览器或重启验收。

## 恢复写入重试边界修正（2026-11-04）
